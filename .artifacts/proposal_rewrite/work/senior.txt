Proyek ini bertujuan mengatasi tantangan yang dihadapi oleh Tim Search and Rescue
(SAR) melalui pengembangan solusi inovatif berupa Alat Skala Edukasi, Evacuating
Map System, dan Website Monitoring. Dengan fokus pada pengoptimalan
penggunaan sumber daya dan peningkatan efisiensi operasional, proyek ini berhasil
menciptakan integrasi yang kokoh antara alat-alat tersebut. Hasilnya, Website
Monitoring yang sederhana namun efisien membantu Tim SAR melihat dan
menganalisis hasil penyisiran, sedangkan Evacuating Map System memberikan
informasi real-time untuk meningkatkan responsibilitas tim dalam menghadapi situasi
darurat. Melalui kontribusi ini, proyek magang ini bukan hanya menyelesaikan
masalah konkret, tetapi juga menciptakan pondasi untuk peningkatan berkelanjutan
dalam operasional Tim SAR, memberikan dampak positif yang signifikan.

                             LATAR BELAKANG
       Bencana alam, seperti gempa bumi, banjir, hingga gunung meletus, seringkali
meninggalkan dampak yang merusak dan mengancam nyawa manusia. Salah satu tantangan
utama dalam menghadapi bencana adalah pasca bencana itu sendiri seperti mengevakuasi warga
yang terdampak dengan cepat dan efisien. Proses evakuasi memerlukan koordinasi yang baik
antara tim penyelamat, informasi yang akurat tentang kondisi lapangan, serta pemahaman yang
mendalam tentang lokasi evakuasi korban.


       Di tengah tekanan waktu serta keterbatasan sumber daya, seringkali sulit bagi tim
penyelamat untuk mengkoordinasikan upaya mereka secara efektif. Informasi yang tidak lengkap
atau tidak akurat akan sangat berdampak buruk pada proses evakuasi pasca bencana. Oleh karena
itu, menjadi penting untuk mencari solusi yang inovatif guna meningkatkan kinerja tim
penyelamat dalam kondisi pasca bencana tersebut.


       Oleh sebab itu, pemanfaatan teknologi Internet of Things (IoT) menawarkan potensi yang
cukup menjanjikan dalam meningkatkan efisiensi dan efektivitas proses evakuasi pasca bencana.
Dengan memanfaatkan sensor-sensor dan perangkat cerdas yang terhubung secara online ,
melacak lokasi tim penyelamat hingga memberikan informasi yang tepat waktu kepada team
yang bersangkutan.


​      Maka dari itu, proyek ini bertujuan untuk mengembangkan sebuah sistem berbasis IoT
yang dapat membantu dalam proses evakuasi pasca bencana. Sistem ini akan memungkinkan tim
penyelamat untuk memantau serta melacak lokasi anggota tim penyelamat dan koordinat lokasi
yang membutuhkan bantuan segera, serta memberikan gambaran tentang rute evakuasi yang
optimal berdasarkan kondisi terkini.


​      Dengan adanya sistem ini, diharapkan proses evakuasi pasca bencana dapat dilakukan
dengan lebih cepat, efisien, dan aman, sehingga mengurangi risiko korban jiwa. Selain itu, sistem
ini juga dapat menjadi alat yang berharga dalam upaya pemulihan pasca bencana , dengan

                       ANALISA FUNGSIONAL
Analisa Kebutuhan fungsional merupakan gambaran mengenai fungsi-fungsi yang dapat
dilakukan oleh sistem ini. Kebutuhan fungsional sistem meliputi:
    1.​ Sistem IOT dalam skala edukasi.
    2.​ Perangkat pengoperasian (laptop) harus terinstal php (Xampp) dan Node.js untuk
        menjalankan Website Dashboard.
    3.​ Perangkat pengoperasian (laptop) harus terinstal Arduino IDE untuk menjalankan
        konfigurasi Sistem Benam.


Cara kerja
Sistem Benam :
    1.​ Sambungkan perangkat ke sumber daya (power bank / ac adapter).
    2.​ Sesuaikan konfigurasi Wifi di arduino IDE.
    3.​ Alat siap digunakan.

Website Dashboard :
  1.​ Pastikan Database sudah di import ke Xampp (mySQL).
  2.​ Jalankan Program folder Backend di Visual Studio Code ( Command : “ composer start ”
       ).
  3.​ Jalankan Program folder Frontend di Visual Studio Code ( Command : “ npm run dev “
       ).
  4.​ Website siap digunakan.

Komunikasi antara Sistem Benam dan Website :
  1.​ Sesuaikan konfigurasi MQTT di arduino IDE.
  2.​ Sesuaikan konfigurasi MQTT pada folder MQTT di Visual Studio Code, untuk
      menjalankan program gunakan ( Command : “ node index.js “ ).
  3.​ Setelah masuk pesan “ MQTT Connected “ maka komunikasi antara alat dan website
      dashboard sudah siap digunakan.

Batasan Kemampuan Proyek

   1.​ Keterbatasan Jaringan:
          ○​ Sistem hanya dapat beroperasi dalam jaringan lokal yang sama untuk komunikasi
             antara alat IoT dan dashboard.
          ○​ Komunikasi Sistem Benam serta Website Dashboard hanya didukung dalam
             penggunaan jaringan yang sama.
          ○​ Kualitas sinyal WiFi dapat mempengaruhi keandalan komunikasi data.

Dalam pengembangan untuk lomba Gemastik ini kami membagi menjadi 3 tahapan lanjutan

Tahap 1 (Pengembangan proyek 50% / penyisihan 1)
Pada tahap 1 pengembangan proyek ini dianggap tercapai apabila berhasil memenuhi kebutuhan
sesuai dengan diagram blok berikut :




Pada diagram blok di atas, dijelaskan alur data yang dikirimkan oleh pengguna (tim SAR).
Dalam kasus ini, tim SAR mengirimkan status melalui tombol (input warna hijau/kuning/merah).

   1.​ Tombol Aman, Tombol Warning, Tombol SOS: Tim SAR dapat memilih salah satu
       dari tiga tombol ini untuk mengirimkan status mereka. Tombol hijau menunjukkan
       kondisi aman, kuning untuk peringatan, dan merah untuk situasi darurat (SOS).
   2.​ OTOMASI 3 Menit: Jika dalam waktu 3 menit sejak terakhir kali tombol ditekan tidak
       ada input baru dari pengguna, data status serta lokasi (latitude dan longitude) akan secara
       otomatis dikirim tanpa perlu menekan tombol lagi.




                                                                                               19
   3.​ GPS (UBLOX NEO-6M): Modul GPS digunakan untuk mendapatkan data lokasi, yaitu
       latitude dan longitude.
   4.​ Microcontroller (ESP32): Mikrokontroler ESP32 digunakan untuk mengelola data yang
       diterima dari tombol dan modul GPS. Mikrokontroler ini akan mempersiapkan data untuk
       dikirim.
   5.​ Communication (MQTT): Setelah data dipersiapkan, data latitude dan longitude beserta
       status akan dikirim melalui protokol komunikasi MQTT (Publish). Data ini kemudian
       akan diterima oleh penerima MQTT (Subscribe).
   6.​ Database (Xampp MySQL): Data yang diterima melalui MQTT akan dimasukkan ke
       dalam database yang menggunakan Xampp dan MySQL.
   7.​ Backend: Backend server akan mengelola dan memproses data yang ada di dalam
       database.
   8.​ Dashboard UI: Data yang telah diproses kemudian akan ditampilkan di Dashboard
       Website Monitoring untuk pemantauan oleh tim SAR dan pihak terkait lainnya.

Dengan demikian, seluruh proses mulai dari pengiriman status oleh tim SAR hingga penampilan
data di dashboard website dilakukan secara terintegrasi dan otomatis, termasuk fitur otomasi
yang mengirim data setiap 3 menit jika tidak ada input baru dari pengguna.

Tahap 2 (Pengembangan proyek 75% / Penyisihan 2)

Pada tahap 2 pengembangan proyek ini dianggap tercapai apabila berhasil memenuhi kebutuhan
sesuai dengan diagram blok berikut :




Pada diagram blok di atas, dijelaskan alur data yang dikirimkan oleh pengguna (tim SAR)
dengan menggunakan transmitter-receiver untuk pengiriman data tanpa internet. Dalam tahapan
lanjutan ini, komunikasi MQTT tetap digunakan untuk mentransfer data dari receiver ke
database dan dashboard UI. Berikut adalah alur lengkapnya:

   1.​ Tombol Aman, Tombol Warning, Tombol SOS: Tim SAR dapat memilih salah satu
       dari tiga tombol ini untuk mengirimkan status mereka. Tombol hijau menunjukkan
       kondisi aman, kuning untuk peringatan, dan merah untuk situasi darurat (SOS).
   2.​ OTOMASI 3 Menit: Jika dalam waktu 3 menit sejak terakhir kali tombol ditekan tidak
       ada input baru dari pengguna, data status serta lokasi (latitude dan longitude) akan secara
       otomatis dikirim tanpa perlu menekan tombol lagi.
   3.​ GPS (UBLOX NEO-6M): Modul GPS digunakan untuk mendapatkan data lokasi, yaitu
       latitude dan longitude.
   4.​ Microcontroller (ESP32): Mikrokontroler ESP32 digunakan untuk mengelola data yang
       diterima dari tombol dan modul GPS. Mikrokontroler ini akan mempersiapkan data untuk
       dikirim.



                                                                                               21
   5.​ Transmitter (NRF24L01/Lora): Data yang telah dipersiapkan oleh mikrokontroler akan
       dikirimkan melalui transmitter NRF24L01 atau Lora, yang menggunakan sinyal frekuensi
       radio untuk mentransmisikan data.
   6.​ Receiver (NRF24L01/Lora): Data yang dikirimkan oleh transmitter akan diterima oleh
       receiver yang kompatibel (NRF24L01 atau Lora).
   7.​ Mikrokontroller (ESP32): Mikrokontroler kedua akan menerima data dari receiver dan
       mempersiapkannya untuk dikirim menggunakan protokol komunikasi MQTT.
   8.​ Communication (MQTT): Mikrokontroler kedua akan menggunakan MQTT untuk
       mengirim data yang diterima dari receiver ke database.
   9.​ Database (MySQL): Data yang diterima melalui MQTT akan dimasukkan ke dalam
       database yang menggunakan MySQL.
   10.​Dashboard UI: Data yang telah diproses dan disimpan dalam database akan ditampilkan
       di Dashboard Website Monitoring untuk pemantauan oleh tim SAR dan pihak terkait
       lainnya.

Algoritma A Star adalah algoritma pencarian terbaik yang menggabungkan Pencarian Biaya
Seragam (Uniform Cost Search) dan Pencarian Terbaik-Greedy (Greedy Best-First Search). Jarak
yang diperoleh berasal dari perhitungan jarak aktual (biaya aktual) ditambah dengan jarak
perkiraan (biaya perkiraan) (Suhendri et al., 2021; Sunaryo et al., 2016).

Algoritma A* (A-star) adalah algoritma graf traversal dan pathfinding yang dirancang untuk
menemukan jalur terpendek antara dua titik dalam graf. A* adalah pengembangan dari algoritma
Dijkstra, yang menggabungkan kelebihan dari Dijkstra dan algoritma Greedy Best-First Search.

A* bekerja dengan menggunakan fungsi evaluasi              untuk setiap node    , yang merupakan
jumlah dari dua komponen:

   ●​        : Biaya dari node awal ke node nnn saat ini. Ini adalah jarak aktual yang telah
        ditempuh dari titik awal.
   ●​      : Estimasi biaya terpendek dari node nnn ke node tujuan. Ini adalah heuristik yang
        memandu pencarian jalur.

Pendekatan heuristik dalam pathfinding penting karena meningkatkan efisiensi dengan mempercepat pencarian jalur
melalui perkiraan jarak atau biaya, sehingga mengurangi waktu komputasi dan jumlah node yang harus dieksplorasi.
Heuristik membantu algoritma fokus pada area graf yang relevan, menghindari eksplorasi yang tidak perlu, dan
sering kali memberikan solusi yang "cukup baik" dengan cepat, terutama dalam graf yang besar dan kompleks,
sehingga cocok untuk aplikasi real-time atau dengan keterbatasan sumber daya.
